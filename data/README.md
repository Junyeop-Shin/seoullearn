# 서울런 멘토 업무 지원 AI 에이전트: 데이터와 평가 자료

개발 전에 준비하는 자료 모음이다. RAG 원본 문서, 평가셋, 보고서 양식 스키마, 가상 멘티 데이터가 들어 있다. RAG 기본 자료는 「2026 서울런 멘토단 활동가이드 Ver.5 (2026.06.29)」이고, 운영사무국 공지를 보조 자료로 둔다.

## 폴더 구조

```
eval/
  eval_set.json           매뉴얼 Q&A 평가셋 70문항 (v1·v2 정답, 근거, 문의처)
  eval_set_review.xlsx    검수용 엑셀 (eval_set.json에서 자동 생성)
forms/                    보고서 양식 스키마 6종 (forms/README.md 참고)
synthetic/                가상 멘티 4명과 회차 기록 (synthetic/README.md 참고)
scripts/
  validate_docs.py        RAG 원본 문서 형식 검사
  check_eval_set.py       평가셋 검사 + 검수용 엑셀 생성
  check_project_data.py   양식 스키마·가상 데이터 검사
data/
  manual/                 활동가이드 본문, 섹션 단위 마크다운 (18개)

  places/                 협약 장소 화면에 쓰는 임시 장소 목록 (study_cafes_temp.json: 카카오맵 검색으로 찾은 스터디카페, 실제 협약 장소 아님)
```

## 코퍼스 버전

평가 전후 비교를 위해 색인 범위를 버전으로 나눈다.

| 버전 | 포함 자료 | 용도 |
| --- | --- | --- |
| v1 | data/manual | 기본형 측정, 검색·청킹 개선 효과 측정 |
| v2 | v1 + data/notice (status: active) | 공지 추가 효과 측정, 실제 서비스 |

평가셋의 각 문항에 v1 정답과 v2 정답을 따로 적어 둔다. 예를 들어 "시간확대는 누가 신청하나요?"는 v1에서는 "멘토(활동가이드 5-1)", v2에서는 "2026.8.10.부터 멘티 직접 신청(N06)"이 정답이다.

## 문서 규칙

### 파일 하나 = 섹션 또는 공지 하나

- 매뉴얼: `섹션번호_제목.md` (목차 1-1, 2-3 등을 그대로 따름)
- 공지: `N번호_제목.md`

### Front matter

| 필드 | 의미 | 매뉴얼 | 공지 |
| --- | --- | --- | --- |
| doc_id | 문서 고유 ID | manual-2026-2-5 | notice-2026-n06 |
| title | 제목 | ○ | ○ |
| doc_type | 자료 유형 | manual | notice |
| source | 출처 | 활동가이드 | 운영사무국 공지 등 |
| section, pages | 매뉴얼 섹션·인쇄 페이지 | ○ | - |
| version | 판 | Ver.5 | - |
| published | 발행·게시일 | 2026-06-29 | 모르면 unknown |
| valid_from, valid_until | 효력 기간 | - | ○ |
| status | active / expired | - | ○ |
| recurring | 매년 반복 공고 여부 | - | 해당 시 yearly |
| mentoring_type | 문서 전체의 유형 | 공통·온라인·오프라인 | 〃 |
| related | 관련 문서 ID | - | ○ |
| supersedes | 이 문서가 내용을 바꾸는 문서 ID | - | ○ |
| aliases | 검색 보조 키워드 | ○ | ○ |

### 청크 단위 표시

각 `##` 제목 바로 아래에 주석을 둔다. 청킹 스크립트가 이 주석을 읽어 청크 메타데이터를 만든다.

```
## 일정 변경
<!-- page: 23 | type: 공통 -->
```

- `page`: 매뉴얼은 하단에 인쇄된 페이지 번호(PDF 파일 페이지 = 인쇄 번호 + 1), 공지는 원문 페이지가 있으면 그 번호, 없으면 `-`
- `type`: 해당 청크가 적용되는 멘토링 유형

### 작성 원칙

- 내용은 원문 그대로 옮기고, 이미지 안의 표와 글자도 텍스트로 옮겼다.
- 원문이 개조식이라도 검색에 걸리도록 주어와 서술어가 있는 문장으로 정리했다.
- 표는 행 하나가 하나의 사실이 되도록 다시 짰다. (PDF 텍스트 추출 시 p.36 출결 규정 표의 온라인·오프라인 칸이 섞이는 문제가 있었다.)
- 정리자가 덧붙인 판단이나 메모는 문서 본문에 넣지 않고 이 README에만 적는다.

## 매뉴얼과 공지가 충돌할 때

답변 생성 규칙:

1. `supersedes`로 연결된 경우, 효력 기간 안의 최신 공지를 우선한다.
2. 답변에 두 근거를 모두 표시하고 "활동가이드에는 ~였으나 ○○ 공지로 변경됨"이라고 알린다.
3. `status: expired` 문서는 검색에서 뺀다. 다만 `recurring: yearly`(매년 반복되는 공고)는 '지난 공고'로 남겨, 질문이 그 주제를 직접 물을 때 "지난 공고 기준"이라고 밝혀 쓰고 올해 공고를 새로 확인하라고 안내한다. 이때 답변은 '일부만 답함'으로 처리하고 운영사무국을 문의처로 준다. (지금 해당하는 문서: N03 2025년 서울선순환인재 장학금)

## 문의처 구분 (현직 멘토 확인, 2026-10-07)

활동가이드 p.62 표는 담당 범위를 예시로만 적고, 본문은 '담당자(이음단 또는 운영사무국)'를 섞어 쓴다. 문의처 판단은 아래 기준으로 정리해 `ai-server/app/qa.py`의 답변 규칙과 용어집에 반영했다. 비공식 확인이므로 RAG 문서에는 넣지 않았다.

| 문의처 | 맡는 일 |
| --- | --- |
| 멘토링 운영사무국 | 매칭 전 단계(선발·교육, 매칭 조건 변경, 재매칭, 활동중단)와 사업 전체 운영(활동비·가산금, 공지·규정, 장학금, 시간확대 승인 등) |
| 자치구 이음단 | 매칭 이후 실제 멘토링 운영. **온라인·오프라인 모두.** 장소, 일정 변경, 활동보고서 승인·보완, 출결 확인. 운영사무국과 멘토 사이를 잇는 창구 |
| 서울런 학습지원센터 | 멘티의 홈페이지 사용 |

- 이음단과는 카카오톡 오픈채팅으로 연락한다. 주소가 자치구마다 달라서 멘토가 화면에서 한 번 입력하면 브라우저에 저장하고, 질문할 때 함께 보낸다. 서버는 저장하지 않는다.
- 매칭정보 변경·활동중단은 운영사무국 공지(N04)의 구글폼으로 신청한다. 멘티 연락 부재로 인한 재매칭은 사전연락확인서를 운영사무국에 내고 플랫폼에서 재매칭을 요청한다(2-3). 회기 도중 활동중단할 때 이음단에도 알려야 하는지는 문서에 없다.

## 확인이 필요한 부분

- **공지 게시일:** N03을 뺀 공지 9개의 `published`가 unknown이다. 날짜를 알면 채워야 최신성 판단이 정확해진다.
- **HWP 파일:** 장학금 공고와 함께 받은 HWP 파일(2번 첨부)은 이 환경에서 열 수 없어 반영하지 못했다. 공고문 내용상 자기소개서 지정서식일 가능성이 높다. 필요하면 PDF로 변환해 다시 받는다.
- **친화·성장활동 증빙 사진:** 본문(p.58)은 멘토·멘티 얼굴이 식별 가능해야 한다고 하지만, 부록 계획서·보고서 서식은 "얼굴 노출X"로 안내한다. 2026 공지(N11)는 시작·종료 인증 사진에 얼굴이 식별 가능해야 한다고 적어 본문과 같다.
- **친화·성장활동의 바뀐 점:** N11은 "작년 운영사항과 변경된 부분이 있다"고만 하고 무엇이 바뀌었는지는 적지 않았다. 신청서 구글폼의 주소와 실제 문항도 받지 못했다(결과보고서 제출 링크만 있음).
- **가입 대상 소득 기준:** 활동가이드(Ver.5)는 중위소득 60% 이하로 적혀 있으나, 서울시는 2026년 7월 기준을 80% 이하로 완화했다고 발표했다.
- **공지 첨부 작성예시(templates/2026):** 2026 보고서 공지(N05)에 첨부된 공식 서식이다. 양식 구조는 2026 기준이지만 예시 내용은 2025년 것이 그대로 남아 있다(파일 수정일 2025-03-05, 예시 날짜 2025년). 종합계획서·완료보고서는 활동가이드 부록과 항목이 같다. 주간 활동보고서는 부록과 세 군데가 다르다: 시간 기준 플랫폼이 '구루미'로 적혀 있음(2026은 서로온), '타 플랫폼 이용 시 예약 링크 기재' 안내가 있음(2026은 타 플랫폼 원칙적 금지), 출석·종료 인증사진 칸이 보고서 안에 있음(부록은 활동보고 인증 서식으로 분리). 양식 스키마는 두 자료의 공통 항목으로 만들고, 이 세 가지는 운영 측 확인 후 반영한다.

## 표 데이터는 RAG가 아니라 조회로

`notice/attachments/2025_서울선순환인재장학금_대학리스트.csv`(414개 대학, 서울·비서울 구분)처럼 행이 많은 표는 청크로 쪼개 검색하면 정확도가 떨어진다. "우리 학교가 서울 소재로 인정되나요?" 같은 질문은 이 CSV를 조회하는 도구 함수로 답한다. 활동비 계산도 같은 이유로 규칙 함수로 처리한다.

## 추가 자료를 넣을 때

1. 자료 유형에 맞는 폴더에 같은 front matter 형식으로 추가한다.
2. 기존 매뉴얼 내용을 바꾸는 공지면 `supersedes`를 채우고 위 충돌 표에 한 줄 추가한다.
3. 평가셋에서 새 자료로 정답이 바뀌는 문항은 v2 정답을 갱신한다.
