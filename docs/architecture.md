# 아키텍처

서울런 멘토 업무 지원 서비스의 구성요소, 요청이 흐르는 길, 그리고 데이터가 어디에 남고 어디에 남지 않는지를 정리한다.

## 구성요소

```
                    ┌──────────────────────────────── 멘토의 브라우저 ────────────────────────────────┐
                    │  Vue 화면                                                                        │
                    │  · 보관함 (IndexedDB): 초안, 사전 연락 답변, 인계 요약                            │
                    │  · 설정 (localStorage): 멘토 이름·연락처·소속                                     │
                    └───────────────────────────────────────┬──────────────────────────────────────────┘
                                                            │ /api (같은 출처, 세션 쿠키 + CSRF 토큰)
                                                  ┌─────────▼─────────┐
                                                  │ frontend (nginx)  │  정적 파일, /api를 backend로 전달
                                                  └─────────┬─────────┘
                                                  ┌─────────▼─────────┐
                                                  │ backend           │  로그인·역할, 양식 스키마, 장소 목록,
                                                  │ (Spring Boot)     │  AI 서버 중계 (본문은 해석·저장하지 않음)
                                                  └───┬───────────┬───┘
                                        회원 테이블   │           │ /qa, /chat, /drafts/**, /tools/**
                                              ┌───────▼──┐   ┌────▼──────────────┐        ┌──────────────┐
                                              │ db       │◄──┤ ai-server         ├───────►│ LLM API      │
                                              │ Postgres │   │ (FastAPI)         │ 가린 글만│ (OpenAI 등)  │
                                              │ +pgvector│   │ 가드, RAG, 양식 엔진│        └──────────────┘
                                              └──────────┘   └───────────────────┘
                                        매뉴얼·공지 색인
```

| 구성요소 | 기술 | 맡는 일 |
| --- | --- | --- |
| frontend | Vue 3, Vite, nginx | 화면. 초안과 설정을 브라우저에 보관. 모든 요청은 같은 출처의 `/api`로만 보낸다 |
| backend | Spring Boot 4.1, Java 21 | 로그인(세션 쿠키)·역할(멘토, 관리자), 로그인 실패 제한, 양식 스키마와 장소 목록 제공, AI 서버 중계 |
| ai-server | FastAPI, LangChain, LangGraph | 개인정보 가드, 매뉴얼 Q&A(RAG), 의도 분류, 양식 엔진, 활동비 계산 |
| db | PostgreSQL 16 + pgvector | 회원 테이블, 매뉴얼·공지 벡터 색인, (켰을 때만) 답 못 한 질문 모음 |
| LLM | `init_chat_model`로 교체 가능 | 문장 생성. 숫자 계산과 검증은 맡기지 않는다 |
| 임베딩 | `dragonkue/multilingual-e5-small-ko-v2` (로컬) | 질문과 문서를 벡터로 바꾼다. 외부로 나가지 않는다 |

## 요청 흐름

### 매뉴얼 질문 (`POST /api/chat`)

1. backend가 로그인과 CSRF 토큰을 확인하고 본문을 그대로 ai-server로 넘긴다.
2. **가드:** 이름·전화번호·이메일·학교명을 가린다. 아동 안전 신호가 있으면 여기서 멈추고 운영사무국 즉시 보고 안내를 돌려준다. 검색도 LLM 호출도 하지 않는다.
3. **의도 분류:** 규칙(키워드)으로 먼저 나누고, 애매할 때만 LLM에 묻는다.
   - 금액 질문("시간당 얼마") → 활동비 계산기(규칙 함수). LLM 없음.
   - 보고서·계획서 작성 요청 → 해당 화면 안내와 입력 항목.
   - 그 밖 → 매뉴얼 Q&A.
4. **검색:** 벡터 검색과 BM25를 순위로 합치고(하이브리드), 용어집으로 멘토 말투를 공식 용어로 보강한다. 상위 5개 청크를 고른다.
5. **답변 생성:** LLM에 가린 질문과 5개 청크만 보낸다. 출력은 JSON(답변가능 여부, 답변, 인용, 문의처)이고, 형식이 틀리면 오류로 기록한다.
6. **문의 초안:** 답을 다 못 했으면 문의처에 보낼 글 초안을 만든다. 연락처는 LLM이 아니라 코드가 붙인다.
7. 응답에 근거 쪽수, 문의처, 가린 개인정보 종류를 담아 돌려준다. 로그에는 길이와 결과 유형만 남는다.

### 보고서 초안 (`POST /api/drafts/{form_id}`)

1. 화면이 양식 스키마(`forms/*.json`)로 입력 칸을 그린다. 개인정보 칸은 입력 칸이 없다.
2. 양식 엔진이 필드의 `source`에 따라 처리한다.

| source | 처리 | LLM |
| --- | --- | --- |
| user | 멘토가 고르거나 넣은 값을 그대로 쓴다 (5점 척도, 시간, 회차) | 쓰지 않음 |
| placeholder | `[멘티명]` 같은 자리표시. 입력이 와도 버리고 경고한다 | 쓰지 않음 |
| derived | 규칙 함수로 계산한다 (기간, 수행 리스트, 제출 기한) | 쓰지 않음 |
| user_text | 멘토가 쓴 사실을 문장으로 다듬기만 한다 | 가린 글만 |
| llm_draft | 입력을 바탕으로 초안을 쓴다 | 가린 글만 |

3. LLM에 보내기 전에 가드로 가리고, 활동보고서·완료보고서는 정서·가정·건강 내용을 문장 단위로 걸러낸다.
4. LLM 출력에 입력에 없는 숫자가 있으면 그 문장을 빼고 경고한다. 한 번 더 가드로 가린다.
5. 빠진 필수 항목은 되물을 질문으로, 제출 기한과 증빙은 안내로 돌려준다.
6. 멘토가 고친 초안은 화면이 브라우저 보관함에 저장한다. 서버는 응답을 보낸 뒤 아무것도 갖고 있지 않다.

### 멘토 교체 인계 (`POST /api/drafts/handover_summary`)

허용 목록 방식이다. 출석 패턴, 과제 수행, 학습 태도, 수강 강의·진도 네 항목마다 그 항목의 출처 칸만 모아 LLM에 따로 묻는다. 학습이해도, 멘토링 메모, 건의사항 칸은 LLM에 아예 보내지 않는다. 결과에 학업 수준·정서 표현이 섞이면 문장째 뺀다.

## 데이터가 남는 곳과 남지 않는 곳

| 데이터 | 멘토 브라우저 | backend | ai-server | db | 로그 | LLM 제공사 |
| --- | --- | --- | --- | --- | --- | --- |
| 멘티 이름·학년, 멘토 이름·연락처·소속 | 보관함과 localStorage. 초안의 자리표시를 화면에서 채운다 | 보내지 않음 | 보내지 않음 | 저장 안 함 | 남기지 않음 (화면 주소는 웹 서버 로그에서 제외하고, 요청의 Referer에는 출처만 싣는다: `index.html`의 `referrer` 메타. 플랫폼에서 복사해 붙여 넣은 활동보고서는 이름 칸이 들어 있어 브라우저에서 나눈다) | 전달 안 함 |
| 멘티 연락처·학교 | 입력받지 않음 | - | - | - | - | - |
| 질문 원문 | 화면에만 (새로 고치면 사라짐) | 중계만 | 처리 후 버림 | 저장 안 함 | 길이만 | 가린 글만 전달 |
| 질문에 섞여 들어온 이름·전화번호·학교명 | 화면에만 | 중계만 | 가드에서 가림 | 저장 안 함 | 종류만 ("학교명") | 전달 안 함 |
| 보고서 입력과 초안 | 보관함 (IndexedDB) | 중계만 | 처리 후 버림 | 저장 안 함 | 양식 이름과 개수만 | 가린 글만 전달 |
| 정서·가정·건강 내용 (활동보고서, 완료보고서, 종합계획서) | 보관함 (멘토가 쓴 그대로) | 중계만 | 걸러냄 | 저장 안 함 | - | 전달 안 함 |
| 인계 요약 | 보관함 | 중계만 | 처리 후 버림 | 저장 안 함 | 개수만 | 허용 항목의 출처 칸만 |
| 이음단 카카오톡 채널 주소 (자치구별, 공개 주소) | 화면 자료 (`frontend/public/data/eumdan_channels.json`) | 보내지 않음 | 보내지 않음 | 저장 안 함 | - | 전달 안 함 |
| 회원 정보 | - | 세션 | - | 아이디, 비밀번호 해시, 역할 | 남기지 않음 | - |
| 로그인 실패 기록 | - | 메모리 (재시작하면 사라짐) | - | 저장 안 함 | 남기지 않음 | - |
| 매뉴얼·공지 | - | - | 색인 | 청크와 임베딩 | - | 검색된 청크 |
| 답 못 한 질문 (기본 꺼짐) | - | 관리자 조회 | 켰을 때만 기록 | 가린 문장, 분류, 문의처, 날짜 | - | - |

- LLM 응답 캐시(`.cache/llm_cache.jsonl`)는 평가 실행에서만 쓴다. API 서버는 응답을 디스크에 쓰지 않는다.
- 답 못 한 질문 모음을 켜더라도 아동 안전 신호가 있는 질문, 정서·가정·건강·성적 이야기가 든 질문, 150자를 넘는 질문은 저장하지 않는다. 질문한 사람을 알 수 있는 열은 테이블에 없다.
- 카카오맵에는 장소 이름과 좌표만 전달된다.

### 확인하는 방법

`scripts/e2e_demo.mjs`는 화면을 끝까지 눌러 보면서 브라우저가 서버로 보낸 모든 요청을 모아, 멘티·멘토 이름과 연락처가 한 번도 들어가지 않았는지 확인한다.

`scripts/check_no_leak.py`가 가상 회차 기록(가짜 전화번호, 이름, 학교명, 성적, 정서 메모 포함)으로 질문 10번과 활동보고서 초안 3번을 호출한 뒤, 네 컨테이너의 로그, DB 전체, 캐시 폴더에 보낸 문장의 조각이 남았는지 검사한다. 기능을 추가할 때마다 다시 돌린다.

## 보호 장치의 한계

- 가드와 민감 내용 필터는 규칙(정규식, 낱말 목록)이다. 목록에 없는 표현, 뒤따르는 말 없이 쓰인 일부 줄인 학교명("경기고")은 지나갈 수 있다. LLM 지시문에도 같은 금지 규칙을 넣어 두 번 막지만 보장은 아니다.
- 지어내기 검사는 숫자만 본다. 숫자가 없는 지어낸 문장은 잡지 못한다. 그래서 모든 결과는 초안이고, 멘토가 읽고 고친 뒤 제출한다.
- 가린 글이라도 LLM 제공사로 전달된다. 제공사의 데이터 보관 정책은 계약 조건에 따른다.
- 브라우저 보관함은 암호화하지 않는다. 공용 기기에서는 쓰고 나서 보관함을 지워야 한다.

## 저장소 구조

```
ai-server/    FastAPI AI 서버 (app/: 가드, RAG, 라우터, 양식 엔진 / evaluation/: 평가 실행기 / tests/)
backend/      Spring Boot 업무 백엔드
frontend/     Vue 3 화면
data/         RAG 원본 문서 (manual 18개, notice 11개), 용어집
forms/        양식 스키마 (양식 하나 = JSON 파일 하나)
eval/         평가셋과 리포트
synthetic/    가상 멘티·회차 기록·강좌·장소 (개발과 평가는 이것만 쓴다)
scripts/      데이터 검증, 유출 검사, 재측정, 브라우저 점검
prompts/      양식 초안 프롬프트
templates/    서버가 쓰는 문구 템플릿 (사전 연락, 이음단 장소 요청)
docs/         개발 지침, 업무 흐름(workflow.md), 아키텍처, 데모 시나리오, 결과 문서, 제안서
```
