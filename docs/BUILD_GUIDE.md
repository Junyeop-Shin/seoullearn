# 서울런 멘토 업무 지원 AI 에이전트: Claude Code 단계별 개발 지침

기획서(2026-10-07 판)의 기능을 Claude Code로 한 단계씩 만들기 위한 작업 지시서다. 각 단계에는 목표, 읽을 파일, 만들 것, 완료 기준, 그리고 Claude Code에 그대로 붙여 넣을 지시문이 있다.

- 저장 위치: 저장소의 `docs/BUILD_GUIDE.md`
- 2장 "CLAUDE.md에 넣을 내용"은 저장소 루트의 `CLAUDE.md`로 복사한다. Claude Code는 이 파일을 세션마다 자동으로 읽으므로, 지켜야 할 규칙은 거기에 둔다.
- 이 문서는 단계 진행표다. 단계를 마칠 때마다 체크박스를 채우고 커밋한다.

---

## 1. 진행 방법

### 한 단계를 진행하는 순서

1. 새 세션을 열고 해당 단계의 지시문을 붙여 넣는다.
2. 큰 단계는 먼저 계획만 받는다. 지시문 끝에 "코드 쓰기 전에 계획부터 보여줘"를 붙이고, 계획을 확인한 뒤 진행시킨다.
3. Claude Code가 만든 뒤에는 완료 기준을 하나씩 확인한다. 테스트는 Claude Code가 직접 돌리게 한다.
4. 통과하면 커밋한다. 커밋 메시지는 `[1-3] 리랭커 추가`처럼 단계 번호로 시작한다.
5. 이 문서의 체크박스를 채우고, 다음 단계로 넘어가기 전에 대화를 비운다(이전 단계 맥락이 다음 단계를 흐리지 않도록).

### 지시문 공통 꼬리말

모든 지시문 끝에 아래 문단을 붙인다. 2장 규칙을 다시 상기시키는 용도다.

```text
작업 전 CLAUDE.md와 docs/BUILD_GUIDE.md의 해당 단계를 읽어.
실제 멘티 정보는 쓰지 말고 synthetic/ 가상 데이터만 써.
기존 테스트(ai-server/tests)를 깨지 말고, 새 기능에는 API 키 없이 도는 테스트를 같이 만들어.
끝나면 바뀐 파일 목록, 테스트 결과, 완료 기준 충족 여부를 표로 보고해.
```

### 하지 않을 것

- API 키를 대화에 붙여 넣지 않는다. `.env`에만 둔다.
- 한 지시문에 두 단계 이상을 묶지 않는다.
- 평가 수치가 오르지 않았는데 "개선됨"으로 정리하지 않는다. 수치가 그대로면 그대로라고 기록한다.

## 2. CLAUDE.md에 넣을 내용

아래 블록 전체를 저장소 루트 `CLAUDE.md`로 저장한다.

````markdown
# 서울런 멘토 업무 지원 AI 에이전트

서울런 멘토의 반복 업무(매뉴얼 문의, 활동보고서·종합계획서 작성, 완료보고서, 멘토 교체 인계)를 돕는 서비스.
개인 포트폴리오이자 서울시 제안용. 기획서: docs/BUILD_GUIDE.md 와 기획 문서.

## 절대 규칙
- 멘티 정보는 서버에 저장하지 않는다. DB·로그·캐시 어디에도 보고서 본문, 질문 원문을 남기지 않는다.
  로그에는 길이, 결과 유형, 오류 여부만 남긴다.
- 멘티 성명·학년·연락처, 멘토 성명은 입력받지 않는다. 초안에는 [멘티명] 같은 자리표시를 둔다.
- 사용자 입력은 LLM에 보내기 전에 ai-server/app/guard.py를 거친다 (이름·전화번호·학교명 가리기, 아동 안전 신호 감지).
  아동 안전 신호가 있으면 LLM을 부르지 않고 운영사무국(즉시) 안내를 돌려준다.
- 개발 중에는 Gemini 무료 등급을 쓰므로 synthetic/ 가상 데이터만 쓴다.
- AI는 초안까지만 만든다. 입력에 없는 사실(날짜, 점수, 진도, 상담 내용)을 만들지 않는다.
- 인계 요약은 허용 목록 방식이다. 출석 패턴, 과제 수행, 학습 태도, 수강 강의·진도만 넣고
  학업 수준(이해도·성적)과 정서 상담 내용은 절대 넣지 않는다 (forms/handover_summary.json).
- 활동가이드 원본 PDF(data/raw/)와 서식 원본(data/templates/)은 Git에 올리지 않는다. 저장소는 비공개.
- .env는 커밋하지 않는다.

## 용어 (매뉴얼 공식 명칭을 그대로)
활동보고서(주간보고서 X), 완료보고서(종합보고서 X), 종합계획서①(사전, 플랫폼 입력)·종합계획서②(1회차 후 서식 파일),
서로온 화상시스템, 자치구 이음단, 멘토링 운영사무국, 서울런 학습지원센터. 용어 대응표: data/glossary.csv

## 문의처 기준
- 운영사무국: 매칭 전 단계(선발·교육, 매칭 조건 변경, 재매칭, 활동중단)와 사업 전체 운영(활동비, 공지·규정, 장학금, 시간확대 승인)
- 이음단: 매칭 이후 실제 멘토링 운영, 온·오프라인 공통(장소, 일정 변경, 활동보고서 승인·보완, 출결 확인).
  연락은 카카오톡 오픈채팅. 주소는 멘토 브라우저에만 저장하고 요청마다 보낸다.
- 학습지원센터: 멘티의 서울런 홈페이지 사용
- 운영사무국(즉시): 보호자 갈등, 아동 보호·안전 우려

## 구조
- ai-server/  Python FastAPI AI 서버 (RAG, 양식 엔진, 계획 추천). LangChain init_chat_model로 LLM 교체.
- backend/    Spring Boot 업무 백엔드 (로그인·역할, 양식 스키마 제공, AI 서버 중계)  ← 1단계에서 생성
- frontend/   Vue 3 화면  ← 1단계에서 생성
- data/       RAG 원본 문서(manual, notice), glossary.csv
- eval/       평가셋(eval_set.json), 실행 결과(runs/, Git 제외), 리포트(reports/)
- forms/      양식 스키마 JSON (양식 하나 = 파일 하나)
- synthetic/  가상 멘티·회차 기록·강좌 목차

## 명령
- 테스트: docker compose run --rm ai-server python -m unittest discover -s tests -v
- 데이터 검증: python scripts/validate_docs.py && python scripts/check_eval_set.py && python scripts/check_project_data.py
- 평가: docker compose run --rm ai-server python -m evaluation.run_eval --config <설정> --corpus v1|v2 [--retrieval-only]

## 평가 규칙
- 채점 모델(JUDGE_MODEL)은 개선 전후 비교 내내 바꾸지 않는다.
- 임베딩 모델을 바꾸면 벡터 결과를 모두 다시 잰다.
- 용어집·프롬프트는 평가셋 홀수 번호로 고치고 짝수 번호로 확인한다. 평가셋 문항 문장을 용어집에 그대로 넣지 않는다.
- 개선은 한 번에 하나씩 적용하고, 적용할 때마다 같은 평가셋으로 다시 잰다.

## 코드 규칙
- 사용자에게 보이는 문구는 한국어 존댓말.
- 새 기능에는 API 키 없이 도는 테스트를 함께 만든다 (가짜 LLM: evaluation/run_eval.py의 FakeLLM 참고).
- LLM 출력은 JSON으로 받고 파싱 실패를 오류로 기록한다. 조용히 넘기지 않는다.
- 숫자 계산(회차 배분, 활동비, 날짜 규칙)은 규칙 함수로 하고, LLM은 문장만 만든다.
````


**지시문 (1-A-3)**

```text
임베딩 모델을 비교해. md_vector와 md_hybrid를 v1 --retrieval-only로 세 모델로 돌려:
dragonkue/multilingual-e5-small-ko-v2(기본), BAAI/bge-m3, intfloat/multilingual-e5-large-instruct.
각 모델의 hit@5, MRR, 색인 시간, 질문 1개 평균 검색 시간, 컨테이너 메모리 사용량을 표로 만들어 eval/reports/embedding_choice.md에 저장해.
```

```text
결과에서 fabrication_rate(지어내기), over_refusal_rate(과잉 거절), route_acc(문의처) 기준으로 틀린 문항을 뽑아
eval/reports/baseline_answer.md에 '검색 실패 / 생성 오류 / 온·오프라인 혼동 / 답 없음 처리 실패 / 문의처 오류'로 분류해.
```

**지시문 (1-B-1 리랭커)**

```text
1-B-1을 진행해. 하이브리드 검색 결과 상위 20개를 다시 정렬하는 리랭커를 retrieval.py에 추가하고,
pipelines.py에 md_hybrid_glossary_rerank 설정을 만들어.
한국어를 지원하는 cross-encoder 리랭커 후보를 2개 골라서 크기(파라미터, 메모리)와 함께 제안하고, 내가 고르면 구현해.
리랭커 모델명은 .env(RERANKER_MODEL)로 바꿀 수 있게 하고, 테스트에서는 모델 없이 도는 가짜 리랭커를 써.
구현 후 v1 --retrieval-only로 재서 리랭커 전후 hit@1, MRR을 비교해.
```

**지시문 (1-B-2 용어집)**

```text
1-B-2를 진행해. baseline_retrieval.md에서 '용어 차이'로 분류된 문항 중 홀수 번호 문항만 보고
data/glossary.csv에 멘토 말투 ↔ 매뉴얼 용어 대응을 추가해. 평가셋 질문 문장을 그대로 넣지 말고 일반적인 표현으로 써.
추가 전후로 홀수 문항과 짝수 문항의 hit@5를 따로 계산해서 보여줘. 짝수 문항이 오르지 않으면 과적합으로 보고 알려줘.
```

**지시문 (1-B-3 답변 규칙)**

