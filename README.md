# 서울런 멘토 업무 지원 AI

서울런 멘토가 멘토링 외에 반복하는 일(매뉴얼 확인, 활동보고서·종합계획서·완료보고서 작성, 멘토 교체 인계)을 줄이는 서비스입니다. 활동가이드를 근거로 질문에 답하고 보고서 초안을 만들되, 멘티와 멘토의 이름은 멘토 브라우저 밖으로 내보내지 않고 보고서 내용은 서버에 저장하지 않습니다.

개인 포트폴리오이자 서울시 제안용 시제품입니다. 가상 데이터로만 개발하고 평가했습니다.

> 이 저장소는 비공개입니다. 활동가이드 정리본에 원문 내용이 들어 있습니다.

## 문제

서울런 멘토는 회차마다, 회기마다 같은 일을 되풀이합니다.

- **규정을 찾는다.** 활동가이드는 60쪽이 넘고 공지가 계속 추가됩니다. 지각은 몇 분까지인지, 멘티가 안 오면 어떤 증빙을 남겨야 하는지, 일정은 며칠 전까지 바꿀 수 있는지를 그때마다 찾아야 합니다. 못 찾으면 운영사무국이나 이음단에 묻는데, 어디에 물어야 하는지도 헷갈립니다.
- **보고서를 쓴다.** 회차마다 활동보고서를 7일 안에 내고, 회기마다 종합계획서를 두 번, 완료보고서를 한 번 씁니다. 실제 접속 시간, 증빙 사진, 첨부 파일처럼 빠뜨리면 활동비가 지급되지 않는 항목이 있습니다.
- **인계가 끊긴다.** 멘토가 바뀌면 다음 멘토는 멘티가 어디까지 들었고 과제를 어떻게 해 왔는지 처음부터 다시 파악합니다.

이 일을 AI로 줄이려 할 때 걸리는 것은 멘티가 미성년자라는 점입니다. 보고서에는 출결과 학습 상황에 가정·정서 이야기까지 섞입니다.

## 해결

| 기능 | 내용 |
| --- | --- |
| 매뉴얼 질문 | 활동가이드와 공지에서 답을 찾아 쪽수와 함께 답합니다. 답이 없으면 지어내지 않고 문의처(운영사무국, 이음단, 학습지원센터)와 보낼 글의 초안을 줍니다 |
| 활동보고서 | 플랫폼 입력 칸과 같은 구성으로 적고, 종합계획서의 그 주차 계획과 출결·인강·과제 선택으로 칸을 미리 채웁니다. 제출 기한과 증빙을 안내하고, 결석 회차에는 학습 내용을 만들지 않습니다 |
| 종합계획서 ①·② | 서식의 항목 형식대로 정리합니다. ①은 학년·학기·과목의 교육과정 단원으로, ②는 붙여 넣은 강의 목차로 주차별 커리큘럼을 채웁니다 |
| 완료보고서 | 화면을 열면 저장해 둔 종합계획서와 활동보고서로 플랫폼의 네 칸(멘토링 내용, 학습목표 대비 성취도, 감성케어 상담, 멘티 요청사항 및 해결과정) 초안을 씁니다. 기록이 없는 칸은 비워 둡니다 |
| 인계 요약 | 출석 패턴, 과제 수행, 학습 태도, 수강 진도 네 가지만 뽑습니다 |
| 사전 연락, 오프라인 일정·장소 | 사전 연락 문자, 매월 이음단에 보내는 일정·장소 문구를 템플릿으로 만듭니다 (AI 미사용). 자치구의 협약 장소를 지도에서 봅니다 |
| 그 밖 | 활동비 계산, 협약 장소 지도, 자치구 이음단 연락처, 인증사진 이름 바꿔 압축, 친화·성장활동 기록, 시간확대 요건 확인 |

화면은 멘티 한 명이 메뉴 하나입니다. 멘티를 고르면 사전 연락 → 종합계획서(1회차 전의 ①과 1회차 후의 ②) → 회차별 활동보고서 → 완료보고서 순서의 지금 단계 화면이 열립니다. 오프라인 멘토링의 일정과 장소는 따로 있는 '오프라인 일정·장소' 화면에서 멘티별로 정합니다. 멘토는 고르기와 짧은 메모만 하고, 날짜·과목·지난 과제·이번 주 계획은 저장된 자료에서 채워집니다. 결과는 플랫폼이나 카카오톡에 붙여 넣을 글로 나오고 항목마다 복사 버튼이 있습니다. 자세한 설계는 [docs/workflow.md](docs/workflow.md)에 있습니다.

설계 원칙은 세 가지입니다.

1. **AI는 초안까지만.** 멘토가 읽고 고친 뒤 플랫폼에 직접 제출합니다.
2. **숫자는 규칙으로, 문장만 AI로.** 회차 배분, 제출 기한, 활동비는 코드가 계산합니다. AI가 쓴 문장에 입력에 없는 숫자가 있으면 그 문장을 뺍니다.
3. **모르면 모른다고.** 매뉴얼에 없는 내용은 답하지 않고 문의처로 연결합니다. 아동 안전 신호가 있으면 AI가 답하지 않고 운영사무국 즉시 보고를 안내합니다.

## 구조

```
멘토의 브라우저 ── Vue 화면 · 보관함(IndexedDB): 멘티별 정보와 초안은 여기에만 저장
      │ /api
frontend (nginx) ─► backend (Spring Boot) ── 로그인·역할, 양식 스키마, 중계(본문 저장 안 함)
                          │                          │
                          ▼                          ▼
                    db (PostgreSQL + pgvector)   ai-server (FastAPI) ──가린 글만──► LLM API
                    회원 · 매뉴얼 색인             가드 → 의도 분류 → RAG / 양식 엔진 / 계산기
```

| 구성요소 | 기술 |
| --- | --- |
| ai-server | Python, FastAPI, LangChain, LangGraph, sentence-transformers |
| backend | Java 21, Spring Boot 4.1, Spring Security, JPA |
| frontend | Vue 3, Vite, nginx |
| db | PostgreSQL 16, pgvector |

- **매뉴얼 Q&A:** 활동가이드를 섹션 단위로 다시 정리한 문서 18개와 공지 12개를 청크로 나눠, 벡터 검색과 BM25를 합친 하이브리드 검색에 용어집 질의 확장을 더했습니다.
- **의도 분류:** LangGraph 라우터가 규칙(키워드)으로 먼저 나누고 애매할 때만 LLM에 묻습니다. 금액 질문은 계산기로, 작성 요청은 해당 화면으로 보냅니다.
- **양식 엔진:** 양식 하나가 JSON 파일 하나입니다. 필드마다 누가 채우는지(멘토, 규칙, AI)를 스키마에 적어 두고 엔진이 그대로 따릅니다. 새 서식은 JSON 파일만 추가하면 API에 나옵니다.

자세한 내용은 [docs/architecture.md](docs/architecture.md)에 있습니다.

## 개인정보 설계

| 원칙 | 구현 |
| --- | --- |
| 이름은 브라우저 밖으로 나가지 않는다 | 멘티 이름·학년, 멘토 이름·연락처·소속은 멘토 브라우저에만 저장합니다. 서버가 만든 초안에는 `[멘티명]` 자리표시가 오고 화면이 그 자리를 채웁니다. 멘티 연락처와 학교는 적는 칸이 없습니다 |
| 저장하지 않는다 | 질문과 보고서 내용은 서버의 DB·로그·캐시에 남기지 않습니다. 로그에는 길이와 결과 유형만 남습니다. 초안은 브라우저 보관함에만 있습니다 |
| 가려서 보낸다 | LLM에 보내기 전에 가드가 이름, 전화번호, 이메일, 학교명을 가립니다. 정서·가정·건강 이야기는 보고서 초안의 재료로 쓰지 않습니다 |
| 넘길 것만 넘긴다 | 인계 요약은 허용 목록 방식입니다. 허용 항목의 출처 칸만 LLM에 보내고, 학업 수준과 상담 내용은 보내지도 않습니다 |
| 확인한다 | `scripts/check_no_leak.py`가 가짜 개인정보가 든 가상 기록으로 서비스를 호출한 뒤 컨테이너 로그, DB, 캐시에 조각이 남았는지 검사합니다 |

이 검사는 개발 중에 실제 문제를 하나 잡았습니다. 평가용 LLM 응답 캐시가 API 서버에서도 켜져 있어 답변이 디스크에 쌓이고 있었습니다.

매뉴얼로 답하지 못한 질문을 모아 운영 측의 매뉴얼 보완 자료로 쓰는 기능도 있지만, 서버에 질문을 저장하게 되므로 기본으로 꺼 두었습니다.

## 결과

멘토가 물을 법한 질문 72개(답이 없는 질문 8개, 일부만 답할 수 있는 질문 12개 포함)로 측정했습니다.

### 검색 (활동가이드만, 근거가 있는 68문항)

| 단계 | hit@1 | hit@5 | MRR |
| --- | --- | --- | --- |
| 기본형: 원본 PDF를 500자씩 자르고 벡터 검색 | 44.1 | 82.4 | 0.595 |
| 활동가이드를 섹션 단위 문서로 다시 정리 | 57.4 | 83.8 | 0.683 |
| 벡터 + BM25 하이브리드 | 54.4 | 88.2 | 0.682 |
| 용어집 질의 확장 (최종) | 58.8 | 91.2 | 0.722 |

hit@5는 정답 근거가 검색 결과 상위 5개 안에 있는 문항의 비율입니다. 가장 큰 효과는 문서를 사람이 다시 정리한 데서 나왔습니다.

### 답변 (최종 설정)

| 지표 | 활동가이드만 | 활동가이드 + 공지 | 자료 순서를 섞었을 때 |
| --- | --- | --- | --- |
| 답할 수 있는지 판단 | 80.6% | 83.3% | 80.6~81.9% |
| 지어내기 (답이 없는데 답함) | 8개 중 1개 | 4개 중 1개 | 같음 |
| 과잉 거절 (답이 있는데 거절) | 0% | 3.3% | 1.9~3.8% |
| 문의처 | 86.1% | 86.1% | 76.4~80.6% |
| 아동 안전 질문의 즉시 연결 | 100% | 100% | 100% |

앞의 두 열이 실제 서비스와 같은 조건입니다. 마지막 열은 검색된 자료 5개의 순서만 섞어 두 번 더 잰 값으로, 수치가 얼마나 흔들리는지 보여 줍니다. 문의처 정확도는 자료 순서에 민감합니다.

개선 전 측정(1회)은 답변가능 판단 73.6%, 지어내기 12.5%, 과잉 거절 3.8%, 문의처 73.6%였습니다.

보고서 초안은 가상 사례 14건에서 필수 항목 채움률 100%, 입력에 없는 숫자·날짜 0건, 개인정보·민감 내용 노출 0건이었습니다. 활동보고서 초안을 AI가 쓰던 때의 측정이고, 지금 활동보고서 화면은 AI를 쓰지 않습니다.

위 수치는 2026-10-08에 공지 11개로 잰 값입니다. 그 뒤에 추가한 공지 1개와 가드 규칙 변경은 다시 재지 않았습니다.

단계별 수치와 실패 분석은 [docs/rag_results.md](docs/rag_results.md)와 `eval/reports/`에 있습니다.

### 측정하며 알게 된 것

- **개인정보 가드가 검색을 망치고 있었습니다.** 줄인 학교명 패턴이 "바꾸고", "한다고" 같은 동사를 학교명으로 가려, 72문항 중 7문항의 질문이 손상됐습니다.
- **답변 지표는 생각보다 많이 흔들립니다.** 검색된 자료 5개의 순서만 바꿔도 문의처 정확도가 4~7문항 움직였습니다. 그래서 최종 평가는 순서를 바꿔 세 번 쟀고, 그 범위 안의 차이는 개선으로 치지 않았습니다.
- **리랭커는 검색만 좋아졌습니다.** 1위 적중률을 58.8%에서 77.9%로 올렸지만 답변 지표는 오르지 않았고 CPU에서 질문당 10초가 걸려 넣지 않았습니다. 모델이 상위 5개를 모두 읽기 때문에 순서가 답을 거의 바꾸지 않습니다.
- **LLM 채점은 믿기 어려웠습니다.** 채점 모델이 맞는 답을 0점 처리하는 경우가 확인돼, 결과 표에는 규칙으로 계산한 지표만 실었습니다.

## 실행

```bash
cp .env.example .env          # OPENAI_API_KEY를 넣는다
docker compose up -d frontend ai-server    # backend, db도 함께 뜬다
# http://localhost:3000 에서 멘토 계정을 만들고 시작한다
```

테스트는 API 키 없이 돕니다.

```bash
docker compose run --rm ai-server python -m unittest discover -s tests   # AI 서버
cd backend && ./gradlew test                                             # 백엔드
cd frontend && npm test                                                  # 화면
```

평가 실행, API 목록, 설정값은 [docs/usage.md](docs/usage.md)에 있습니다.

## 한계

- **가상 데이터로만 확인했습니다.** 평가셋, 보고서 사례, 걸러내는 규칙을 모두 한 사람이 만들었습니다. 실제 멘토의 질문과 메모에서는 수치가 달라질 수 있습니다.
- **지어내기를 줄이지 못했습니다.** 자료에 일부만 있는 내용을 다 답한 것처럼 말하는 문제를 프롬프트로 고치려 했으나 효과가 확인되지 않았습니다.
- **보호 장치는 규칙입니다.** 가드와 민감 내용 필터는 정규식과 낱말 목록이라 목록에 없는 표현은 지나갑니다. 지어내기 검사는 숫자만 봅니다.
- **가린 글도 LLM 제공사로 전달됩니다.** 실제 운영 전에 계약 조건과 개인정보 검토가 필요합니다.
- **실제 서식과 맞춰 보지 못한 부분이 있습니다.** 플랫폼 입력 칸의 글자 수 제한, 활동보고서를 복사했을 때의 형식은 추정입니다. 협약 장소는 임시 자료(카카오맵에서 찾은 스터디카페)이고 실제 협약 장소가 아닙니다.
- **공지는 사람이 넣어야 합니다.** 새 공지가 나오면 문서 규칙에 맞춰 추가하고 다시 색인해야 합니다.
