## 먼저 볼 문제 세 가지

### 1. 개인정보 가드가 일반 동사를 학교명으로 가린다

`guard.py`의 짧은 학교명 패턴(`OO고`, `OO중`, `OO초`)이 '~고'로 끝나는 동사를 학교명으로 본다. 72문항 중 7문항의 질문이 LLM과 검색기에 가기 전에 망가졌다.

| 문항 | 원래 질문 | 가드를 거친 질문 |
| --- | --- | --- |
| Q009 | …어디에 물어보라고 해야 돼요? | …어디에 [학교명] 해야 돼요? |
| Q015 | 같은 멘티랑 계속하고 싶으면… | 같은 멘티랑 [학교명] 싶으면… |
| Q022 | 매칭 조건 바꾸고 싶은데… | 매칭 조건 [학교명] 싶은데… |
| Q028 | 멘티가 학습사이트 바꾸고 싶대요… | 멘티가 학습사이트 [학교명] 싶대요… |
| Q029 | …30분 전에 못 한다고 하면… | …30분 전에 못 [학교명] 하면… |
| Q031 | …멘티가 못 온다고 연락 왔어요 | …멘티가 못 [학교명] 연락 왔어요 |
| Q040 | …수업 시간 더 늘려달라고 하세요 | …수업 시간 더 [학교명] 하세요 |

- 7문항 중 5문항(Q022, Q028, Q029, Q031, Q040)이 아래 오답 목록에 있다. Q022와 Q029의 답변에는 질문에 없던 '학교명' 이야기가 그대로 나온다.
- 검색도 가드를 거친 질문으로 하므로 1-A-2의 검색 수치에도 영향이 있다. `md_hybrid_glossary`의 검색 실패 9문항 중 3문항(Q009, Q028, Q031)이 여기에 해당한다. 가드를 고치면 이 문항들이 맞게 될지는 다시 재 봐야 안다.
- 이번 측정은 지금 코드 그대로의 기준이므로 고치지 않았다. 1-B에서 가장 먼저 고치고 검색·답변을 다시 재는 것을 권한다.

### 2. 채점 모델이 맞는 답을 0점 처리하는 경우가 있다

채점 모델은 평가셋의 정답 문장만 보고 채점한다. 매뉴얼에 실제로 있는 내용을 답변이 덧붙이면 '정답에 없는 내용을 지어냈다'고 본다. '근거 없는 내용 포함' 36.1%와 0점 19문항에는 이런 경우가 섞여 있다.

| 문항 | 상황 |
| --- | --- |
| Q003 | 정답 '매월 20일, 전월 말일까지 승인분'과 답변 '다음 달 20일 지급'은 같은 뜻으로 읽을 수 있는데 0점 |
| Q005 | '16회차'는 맞혔는데, 15~16회차에 연장 여부를 정한다는 문장을 덧붙였다고 0점 |
| Q013 | 첨부 위치는 맞혔는데, '7일 이내' 기한을 덧붙였다고 0점 |

세 문항의 덧붙인 내용이 매뉴얼에 실제로 있는지는 이 리포트에서 대조하지 않았다. 채점 점수를 개선 지표로 쓰기 전에 0점 19문항을 사람이 직접 확인해야 한다(`judge.py`가 예정해 둔 `eval/human_check.csv`). 답변가능 판단, 지어내기, 과잉 거절, 문의처 정확도는 규칙으로 계산하므로 이 문제와 무관하다.

### 3. `route` 키가 빠지면 답변 전체를 버린다

Q039, Q053에서 모델이 JSON에 `route` 키를 넣지 않았고, 코드가 `KeyError`로 답변 전체를 실패 처리했다. 과잉 거절 2건이 모두 이것이다. 검색은 둘 다 성공했다.

## 다음 개선 순서 제안

1. **가드의 학교명 오탐 수정.** 검색과 답변 양쪽에 걸리고 고치기 쉽다. 고친 뒤 1-A-2 검색 수치와 이 측정을 다시 잰다.
2. **`route` 키 누락 처리.** 과잉 거절 2건이 모두 이것이다.
3. **채점 0점 19문항 사람 확인.** 채점 점수를 믿을 수 있는지 먼저 정한다.
4. **문의처 규칙.** 본문에 문의처를 쓰고 `route`를 비우는 경우(Q010, Q020)와 이음단·운영사무국 구분(Q024, Q027). Q042는 정답 라벨부터 검토한다.
