# 검색 심화 기법 실험 (2026-10-11)

"더 심화된 RAG 기법을 쓰면 매뉴얼 질문의 성능을 더 올릴 수 있는가"를 측정으로 확인했다. 결론부터 적으면, 검색 쪽에서는 13가지를 재 봐도 측정 오차를 넘는 개선이 없어 아무것도 넣지 않았다. 남은 문제는 검색이 아니라 답변 단계에 있고, 그중 하나(공지가 활동가이드를 바꾼 주제)는 AI 호출 없이 규칙으로 덮었다.

- 측정: 검색 지표만 쟀다(hit@1, hit@5, MRR). 로컬 임베딩과 BM25만 쓰므로 LLM을 부르지 않는다. 답변 지표는 재지 않았다.
- 평가셋: 72문항. v1(활동가이드 85청크)은 근거가 있는 68문항, v2(활동가이드 + 공지 12개, 134청크)는 71문항.
- 규칙: 값을 고르는 일(가중치, 임계값)은 홀수 번호 문항으로 정하고 짝수 번호로 확인했다. 1문항은 약 1.5%p이고, 2문항 이하의 차이는 개선으로 읽지 않았다.
- 스크립트: `ai-server/evaluation/experiments/` (저장소의 검색기를 감싸서 쓰고, 서비스 코드는 바꾸지 않는다).

## 기준선

지금 설정(`md_hybrid_glossary`: 가드 → 용어집 보강 → 벡터 + BM25를 RRF로 합침 → 상위 5개)을 다시 쟀다.

| 코퍼스 | 문항 | hit@1 | hit@3 | hit@5 | recall@5 | MRR |
| --- | --- | --- | --- | --- | --- | --- |
| v1 (활동가이드) | 68 | 58.8 | 83.8 | 91.2 | 78.4 | 0.722 |
| v2 (활동가이드 + 공지 12개) | 71 | 57.7 | 83.1 | 87.3 | 72.3 | 0.700 |

- v1은 최종 평가(`final_eval.md`)와 같다. 같은 날 가드 규칙(이름 조사, 안전 신호, 전화번호 표기)을 고쳤지만 평가셋 질문 가운데 가려지는 문장이 달라진 것은 없어 수치가 그대로다.
- v2는 최종 평가 때(공지 11개, 59.2 / 83.1 / 87.3 / 0.709)와 다르다. 그 뒤에 넣은 공지 N12(공유계정 안내) 때문에 Q009 한 문항이 1위에서 밀렸다. hit@5는 같다.
- 검색 시간은 질문당 16~20ms다(CPU, 임베딩 포함). 응답 시간은 사실상 모두 LLM 호출이다.
- hit@5로 못 찾는 문항은 v1 6개, v2 9개다. 그중 2개(Q002, Q041)는 서비스에서 금액 계산기와 안전 가드가 먼저 가져가 검색을 타지 않는다.

## 재 본 것

hit@1 / hit@5 / MRR, 전 → 후.

| 기법 | v1 | v2 | 판단 |
| --- | --- | --- | --- |
| 문서 머리말의 aliases를 청크 글에 넣기 (BM25와 임베딩 둘 다) | 58.8→63.2 / 91.2→91.2 / 0.722→0.745 | 57.7→59.2 / 87.3→91.5 / 0.700→0.713 | 보류 |
| aliases를 BM25에만 | 58.8→58.8 / 91.2→92.6 / 0.722→0.725 | 57.7→53.5 / 87.3→87.3 / 0.700→0.671 | 기각 |
| aliases를 제목 줄에 | 58.8→66.2 / 91.2→88.2 / 0.722→0.757 | 57.7→57.7 / 87.3→87.3 / 0.700→0.698 | 기각 |
| 공지 우선: 대체된 활동가이드 청크가 걸리면 그 공지를 끌어오기 | 해당 없음 | 공지가 바꾼 8문항의 순위 변화 없음 | 기각 |
| 공지 우선: 5개 안의 공지 청크를 앞으로 옮기기 | 해당 없음 | 57.7→62.0 / 87.3→87.3 / 0.700→0.722 | 기각 |
| 멘토링 유형(온라인·오프라인)이 반대인 청크 내리기 | 58.8→60.3 / 91.2→91.2 / 0.722→0.729 | 57.7→59.2 / 87.3→87.3 / 0.700→0.707 | 기각 |
| RRF 가중치·후보 수·k (96가지 가운데 홀수 문항으로 고름) | 58.8→57.4 / 91.2→89.7 / 0.722→0.708 | 57.7→59.2 / 87.3→91.5 / 0.700→0.716 | 기각 |
| BM25에서 조사 떼기 | 58.8→64.7 / 91.2→89.7 / 0.722→0.744 | 57.7→57.7 / 87.3→87.3 / 0.700→0.699 | 기각 |
| BM25에서 제목·소제목 3배 가중 | hit@5 91.2→88.2 | hit@5 87.3→85.9 | 기각 |
| 검색 점수로 '자료에 답이 없음' 미리 가르기 | AUC 0.67 | AUC 0.66~0.82 | 기각 |
| 같은 문서의 이웃 청크를 함께 주기 | 근거가 든 문항 91.2→91.2, 글자 수 2배 | 87.3→87.3 | 기각 |
| 한 문서에서 최대 3개만 | hit@5 91.2→92.6 | 변화 없음 | 기각 |
| 줄 단위로 찾고 섹션으로 주기 | 58.8→69.1 / 91.2→88.2 / 0.722→0.763 | 57.7→63.4 / 87.3→88.7 / 0.700→0.732 | 보류 |
| 문의처를 묻는 말이면 '문의처별 담당 범위' 청크 넣기 | hit@5 91.2→92.6 | hit@5 87.3→88.7 | 기각 |

판단의 근거를 묶으면 이렇다.

- **hit@5를 3문항 이상 올린 것이 없다.** 가장 큰 것이 서비스에서 검색을 타는 문항 기준으로 2문항(aliases 양쪽, RRF의 한 점)이다.
- **같은 기법이 코퍼스나 넣는 자리에 따라 뒤집힌다.** aliases는 제목 줄에 넣으면 v1에서 3문항이 내려가고, 조사 떼기는 v1에서 오른 1위 적중률이 v2에서는 0이다. RRF에서 홀수 문항으로 고른 값은 v1의 짝수 문항을 3문항 깎고, v2에서 고른 값은 값 하나를 옆으로 옮기면 사라진다.
- **aliases는 과적합 위험이 있다.** 평가셋과 aliases를 같은 사람이 썼고, aliases에 평가 문항과 같은 말('어디에 물어봐요', '활동비 얼마')이 들어 있다.
- **1위 적중률만 오르는 기법은 답을 바꾸지 못한다.** 줄 단위 색인은 1위 적중률을 4~7문항 올리지만 hit@5는 오르지 않는다. 리랭커 실험(`improvement_1b.md`)에서 1위 적중률을 13문항 올려도 답변 지표가 오르지 않는 것을 이미 확인했다. 모델은 상위 5개를 모두 읽는다.
- **검색 점수로는 답이 없는 질문을 가르지 못한다.** 답이 없는 문항 가운데 유사도가 가장 높은 것이 지어내기 문항(Q066)이다. 주제는 가깝고 답만 없는 질문이라, 어떤 경계도 답이 있는 문항의 절반 이상을 함께 막는다.
- **공지 우선은 채점의 착시였다.** 공지 근거가 문서 단위로만 적혀 있어, 그 공지의 아무 청크나 걸리면 적중으로 센다. Q053(시간확대 조건)은 조건이 적힌 공지 청크가 합친 순위 14위인데도 hit@5로 세어지고 있었다. 순서를 바꿔 1위로 올라오는 것은 조건이 없는 다른 청크다.

## 남은 문제는 답변 단계에 있다

최종 평가의 남은 문제 네 가지(특정 활동의 규정을 전체 규정처럼 답함, 일부만 있는 내용을 다 답한 것처럼 말함, 문의처가 자료 순서에 따라 흔들림, 공지가 바꾼 주제에서 바뀐 사실을 밝히지 않음)는 모두 근거가 5개 안에 들어 있는데도 생긴다.

AI 호출 없이 바꾼 것 (2026-10-11 적용):

| 바꾼 것 | 겨냥한 문제 |
| --- | --- |
| 답변이 근거로 쓴 활동가이드 내용을 바꾼 공지가 있으면 화면이 그 공지를 알린다 (문서 머리말의 `supersedes`로 규칙이 찾는다) | 공지가 바꾼 주제 |
| 답변 위에 '자료에 일부만 있습니다', '자료에서 찾지 못했습니다'를 먼저 보여 준다 | 일부만 있는 내용 |
| 근거 카드에서 원문을 펼쳐 볼 수 있다 | 답이 맞는지 멘토가 바로 확인 |
| 문의 초안을 정해진 틀로 만든다 | 답 못 한 질문마다 붙던 LLM 호출 하나를 없앰 |

LLM이 필요해 재지 않은 것:

| 기법 | 겨냥 | 더 드는 호출 | 판단 |
| --- | --- | --- | --- |
| 답변과 함께 근거 구절을 받아 코드로 대조 | 일부만 있는 내용을 다 답한 것처럼 말함 | 없음 (출력만 100~200토큰 증가) | 가장 먼저 해 볼 만하다. 다만 효과를 보려면 72문항을 세 번은 재야 한다 |
| 답변을 따로 한 번 더 검증 | 위와 같음, 범위를 넓혀 답하는 문제 | 질문당 1회 | 같은 목적의 프롬프트 규칙이 두 번 실패했다. 위를 먼저 재 본 뒤에 |
| 질의 재작성·다중 질의·HyDE | 용어 차이로 못 찾는 문항 | 질문당 1회 | 건질 수 있는 문항이 4~7개뿐이고 용어집이 같은 일을 호출 없이 한다 |
| LLM 리랭킹 | 1위 적중률 | 질문당 1회 | 1위 적중률은 답을 바꾸지 못한다 |
| 청크마다 문서 맥락 요약을 붙이는 색인 | 청크만으로 주제가 드러나지 않는 경우 | 색인할 때 40~50만 토큰 | 청크 앞에 이미 '[문서 제목 > 소제목]'이 붙어 있다 |
| 대화 맥락을 반영한 후속 질문 | 사용성 | 후속 질문마다 1회 | 평가셋이 모두 한 번 묻는 질문이라 효과를 잴 수 없다 |

## 한계

- 답변 지표는 하나도 재지 않았다. '보류'로 둔 두 가지(aliases, 줄 단위 색인)는 답변까지 세 번씩 재야 판단이 선다.
- 공지 근거는 문서 단위로만 채점된다. 공지 근거에 소제목을 적어 두면 공지 우선 실험을 제대로 잴 수 있다.
- 짝수 문항은 앞선 개선에서 이미 세 번 확인용으로 쓰였다. 이번에도 여러 번 봤으므로 깨끗한 확인용이 아니다.
- 답이 없는 문항은 v1 8개, v2 4개뿐이다.
